fork (The Classic Unix Shortcut): The OS duplicates the parent process entirely—cloning its memory space, file descriptors, and execution state instantly via a low-level system call. It is lightning-fast, but it comes with a massive trap: if your parent process has active background threads or locked mutexes when it forks, those locks are copied in a broken or half-acquired state, leading to silent, catastrophic deadlocks.

spawn (The Clean Slate): The parent starts a completely fresh, empty Python interpreter from scratch. It doesn't inherit any state, memory, or open handles from your main script. It is 100% safe and deterministic, but it pays a heavy startup and import tax every time a worker is born.

forkserver (The Best of Both Worlds): A clean, single-threaded template server process is launched early. Whenever you need a worker, the parent asks the forkserver to fork a fresh worker from that pristine, unpolluted state.


Step 2: The IPC & Pickling Wall (The Serialization Tax)
Unlike threads (which share the same heap memory and can read a Python variable instantly), processes are completely isolated. They live in entirely separate virtual memory spaces.

How data moves: If your main process wants to send a dictionary, list, or custom object to a worker process in a ProcessPoolExecutor, Python cannot just pass a memory pointer.

The Pickling Tax: Python must run pickle to serialize that object into a byte stream, push it across an operating system pipe or queue, and have the worker unpickle it back into an object on its own heap.

The Takeaway: If your function takes 0.1 milliseconds to compute, but serializing and shipping the data takes 2 milliseconds, multiprocessing will actually be slower than a single-threaded loop. This is why chunking tasks (chunksize) matters.


Step 3: Zero-Copy Shared Memory (multiprocessing.shared_memory)
When you need to process massive datasets (like multi-megabyte arrays or binary buffers) across 4 workers, pickling and copying data over pipes will choke your RAM and CPU.

The POSIX Shared Memory Solution: Python provides multiprocessing.shared_memory, which interacts directly with the OS shared memory segment (stored at /dev/shm on Linux).

Zero-Copy Access: Instead of sending copies of the data to every worker, you allocate a single block of physical RAM once. You pass only the string name of that memory block to the workers. Every worker maps that exact same physical RAM page directly into its own virtual address space, allowing them to read and write to the same data simultaneously without a single byte being serialized.

Step 4: The Copy-on-Write (CoW) Trap & Reference Counting
Even if you use fork to share memory efficiently between parent and child, CPython introduces a subtle trap due to how it manages memory.

Reference Counting (ob_refcnt): Every single time a Python object is accessed, read, or passed around, CPython increments its internal reference count (ob_refcnt) directly in the object's memory header.

The CoW Invalidation: Under a fork model, memory pages are shared between parent and child only until written to. The moment a worker process reads an object, CPython updates its reference counter. That tiny read operation modifies the memory page header, triggering an immediate Copy-on-Write page duplication by the Linux kernel.

The Reality: What you thought was a shared, read-only data structure suddenly gets duplicated across your physical RAM because CPython's internal bookkeeping constantly writes to object headers.

When a multi-threaded process calls fork(), the operating system copies the entire memory space, but it only duplicates the one single thread that called fork().

An OS thread is the smallest unit of CPU execution that the OS kernel schedules.A process is the container (memory + resources); a thread is the worker inside that container that actually runs instructions on a core.Multiple threads inside the same process share that process's memory space and file descriptors, while each thread has its own call stack and CPU register state (like the instruction pointer) so the OS can pause and resume each thread independently.


nterleaving means two or more tasks take turns making progress in overlapping time windows—for example, Thread A runs a few steps, pauses, Thread B runs a few steps, then Thread A continues. Even on a single core, tasks can be interleaved (concurrent). True parallelism means two instructions literally execute at the same physical instant on different cores.

(asyncio can optionally offload blocking calls to a ThreadPoolExecutor if you explicitly ask it to, such as via asyncio.to_thread(...), which does use worker threads.)



File descriptor (fd): An integer handle (0 = stdin, 1 = stdout, 2 = stderr, plus numbers for open files and sockets) that a process uses to refer to an open I/O resource managed by the OS kernel. When you fork(), the child inherits copies of the parent's file descriptors pointing to the same underlying open file/pipe/terminal stream.

Queue buffer: A temporary staging area in memory (or kernel pipe buffer) that holds items that have been sent (put) before the receiver reads (get) them. If producers put items faster than consumers get them—or if a queue isn't drained—that buffer fills up and can block or cause backpressure.


Free-threaded CPython (PEP 703): Starting with Python 3.13 (experimental) and 3.14+ (officially supported free-threaded build, often seen as python3.14t), CPython supports disabling the GIL using fine-grained locks, immortal/biased reference counting, and thread-safe internal structures so threads can run Python bytecode in parallel on multiple cores.

Core concepts that tie all of this together:

Preemptive multitasking & time slices (quanta): How the OS scheduler shares CPU cores across runnable threads/processes.

Concurrency vs. parallelism: Interleaving/progress over overlapping time vs. simultaneous execution across cores.

Synchronization primitives (mutexes / locks): Coordinating access to shared memory/resources to prevent race conditions.

IPC (Inter-Process Communication): How isolated processes exchange data (Pipe, Queue, shared memory).

Process vs. thread address spaces & ABI/FFI: Why processes are isolated containers, threads share a process's address space, and C extensions execute native code inside the calling thread/process.
