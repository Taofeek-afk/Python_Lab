#1. String traversal (Do 15–20 problems)

Examples:

* Count vowels.
* Reverse a string manually.
* Find the first non-repeated character.
* Remove duplicate characters.
* Check if a string is a palindrome.
* Convert `camelCase` to `snake_case`.
* Find the longest word.
* Compress `"aaabbcc"` → `"a3b2c2"`.

**Why?**
Strings teach you:

* loops,
* indexing,
* state (remembering information),
* edge cases.

These skills transfer directly to arrays, files, and many algorithms.

---

### 2. Array/List traversal (20+ problems)

Examples:

* Find the maximum.
* Find the second largest.
* Rotate a list.
* Remove duplicates.
* Move all zeros to the end.
* Find missing numbers.
* Merge two sorted lists.

**Why?**
Lists are the most common data structure you'll use. Traversing them efficiently is a foundational skill.

---

### 3. Counting and frequency problems

Examples:

* Most common letter.
* Character frequencies.
* Word frequencies.
* Find duplicates.
* Majority element.

**Why?**
These introduce dictionaries (hash maps), which solve a huge class of problems efficiently.

---

### 4. Two-pointer problems

Examples:

* Reverse a list in place.
* Check if a string is a palindrome.
* Merge sorted arrays.
* Remove duplicates from a sorted list.

**Why?**
This teaches you how to solve problems without extra memory, a common interview and real-world technique.

---

### 5. Sliding window

Examples:

* Longest substring without repeats.
* Maximum sum of `k` numbers.
* Longest sequence of vowels.

**Why?**
Instead of restarting work every iteration, you learn to reuse previous computation. It's a big step in algorithmic thinking.

---

### 6. Recursion

Examples:

* Factorial.
* Fibonacci.
* Sum of digits.
* Reverse a string recursively.
* Binary search.

**Why?**
Recursion changes how you think about breaking problems into smaller versions of themselves.

---

### 7. Sorting algorithms

Implement:

* Bubble Sort.
* Selection Sort.
* Insertion Sort.
* Merge Sort.
* Quick Sort.

**Don't use `sorted()`.**

**Why?**
Not because you'll write Bubble Sort at work, but because sorting teaches:

* nested loops,
* invariants,
* time complexity,
* debugging.

---

### 8. Linked lists, stacks, and queues

Examples:

* Reverse a linked list.
* Implement a stack.
* Evaluate parentheses.
* Queue with two stacks.

**Why?**
These teach how memory and references work, which makes you a stronger programmer overall.

---

### Why is all of this necessary?

Think of programming like learning a musical instrument.

You don't become a pianist by playing one difficult piece over and over. You become one by practicing scales, chords, rhythm, and finger exercises until they become automatic.

Programming is similar.

Right now, when you write:

```python
string[index + 1]
```

your brain has to stop and think.

After solving enough problems, you'll instinctively ask:

* "Is `index + 1` still within bounds?"
* "What if the list is empty?"
* "What happens on the first iteration?"
* "What happens on the last iteration?"

That's not talent—it's pattern recognition built through repetition.

### If I were designing your practice

I'd have you solve around **100–150** carefully chosen problems in this order:

* **40%** strings and arrays
* **20%** dictionaries and sets
* **15%** recursion
* **15%** sorting and searching
* **10%** stacks, queues, and linked lists

The goal isn't to collect solutions. It's to reach the point where you can look at a new problem and think, *"I've seen this pattern before."* Once that happens, your confidence and speed improve dramatically.

One more recommendation: after every solved problem, spend five minutes asking yourself:

* Could I make this simpler?
* What edge cases did I miss initially?
* What assumptions did I make?
* What did I learn that applies to other problems?

That reflection often teaches as much as solving the problem itself.
