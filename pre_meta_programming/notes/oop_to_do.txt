Core Concepts Tested: Descriptors, Metaclasses, __slots__, and Class Inspection.

The Goal: Build a mini Object-Relational Mapper (ORM) system where classes define their fields using descriptor classes, and a metaclass automatically registers the schema and validates inputs at runtime.

Requirements:
Create a data descriptor class named Field (or specific subclasses like IntegerParam and StringParam) that handles type checking and attribute storage. If someone passes the wrong type, raise a TypeError.

Create a custom metaclass named ModelMeta. When any model class is defined using this metaclass, it should inspect the class namespace, pull out all the Field descriptors, and store them in a class-level dictionary called _schema.

Create a base class Model using ModelMeta. When you instantiate a model (e.g., user = User(age=25, name="Alice")), it should use the schema to validate the incoming keyword arguments against the descriptors before saving them.

Project 2: The Fault-Tolerant Object Pool & Transaction Context Manager
Core Concepts Tested: Object Pooling, Context Managers (__enter__/__exit__), and Exception Suppression/Propagation.

The Goal: Build a resource management system that pools expensive worker objects, allows users to check them out safely using a with statement, and automatically handles rollback and recycling if a failure occurs.

Requirements:
Create a Worker class that has a unique ID and a status (e.g., "IDLE", "BUSY", "DEAD").

Create an ObjectPool class that pre-allocates a fixed number of Worker instances (e.g., a pool of 3). It must have .acquire() and .release() methods.

Build a custom context manager class named PooledTransaction. When entered, it grabs an available worker from the pool. If work succeeds, it releases the worker back to the pool cleanly. If an exception crashes the with block, it marks the worker as "DEAD", discards it, creates a fresh replacement worker for the pool, and cleanly propagates the exception outward.

Project 3: The Auto-Registering Plugin CLI Router
Core Concepts Tested: ABCs, Plugin Metaclass Registries, Container Protocols (__getitem__, __len__, __iter__), and Duck Typing.

The Goal: Build a command-line interface (CLI) plugin router where adding a new command file automatically registers it into a global registry, and the router acts as an iterable container.

Requirements:
Create an Abstract Base Class named BaseCommand with an abstract method execute(self, args).

Create a metaclass named CommandRegistryMeta that automatically registers any subclass of BaseCommand into a centralized dictionary based on a class-level attribute command_name.

Create a CommandRouter class that implements the container and sequence protocols (__len__, __getitem__, __iter__) using the registered metaclass data. This allows you to loop through all available commands using a standard for loop or check if a command exists using in.
