Deep & Concise Summary of Python Memory Allocation

Variables are References, Not Containers:
A Python variable is a lightweight name tag (pointer) stuck onto an object in memory. It does not physically hold data like a rigid "box" in static languages (e.g., Java).

No Real Primitive Types: 
Because everything is an object, even basic types like int, float, bool, and str are complete class instances containing hidden metadata headers (ob_type).

Dynamic Data Typing: 
Type headers live on the object, not the variable. Python checks this header at runtime (line-by-line execution) to verify what operations (like math or string concatenation) are valid.

Immutable Memory Handling:
 Basic types are immutable. When an integer grows or changes, Python does not resize it in place; it creates a brand-new object elsewhere in memory and moves the variable's reference tag to it.

Integer Interning Optimization:
 To save space, Python pre-allocates a static pool of integers from -5 to 256 during startup. Multiple variables assigned to these numbers share the exact same memory ID.

Automatic Garbage Collection:
 Python tracks how many references point to an object. The instant an object’s reference count hits zero, it is deleted from memory. A secondary generational garbage collector sweeps away "circular reference" islands.

Lazy Evaluation via Iterators:
 Iterators and generators avoid mass memory allocation by generating and calculating exactly one item at a time, exactly when requested.
